# AI-Driven SDUI Code Review Workflow

This document outlines the systematic developer review guidelines for code generated by Antigravity (AI coding assistant). Use this list to verify additions before accepting merges.

---

## 🟢 What to Accept (Best Practices)

1. **Exhaustive Typings**:
   - Every new component must register its props shape in [types.ts](file:///c:/Users/ddaya/Cars24/schema/types.ts).
   - Any new action type must extend the closed `SduiAction` discriminated union.
2. **Decoupled Components**:
   - Components must receive *only* `props` (already resolved by the renderer) and `onAction`.
   - Side effects must be dispatched exclusively via `onAction`.
3. **Pure Math Calculations**:
   - Formulas and computations (like EMI amortization) must be separated into pure, testable modules under [computed.ts](file:///c:/Users/ddaya/Cars24/sdui/computed.ts).
4. **Graceful Fallbacks**:
   - Unknown schema tags must fallback to `UnknownComponentFallback` rather than throwing exceptions or crashing the app viewport.
5. **Versioning Enforcement**:
   - Version gates (`minAppVersion > CURRENT_APP_VERSION`) must be respected before rendering sections.

---

## 🔴 What to Reject (Anti-Patterns)

| Reject Pattern | Reason for Rejection |
| :--- | :--- |
| **Context Leaks** | Components importing `useNavigation` or accessing global contexts directly. All routing/navigation belongs in the centralized [actionEngine.ts](file:///c:/Users/ddaya/Cars24/sdui/actionEngine.ts). |
| **Hardcoded Math** | Math formulas (like EMI divisions) embedded directly inside render blocks. Makes verification and unit testing impossible. |
| **Loose Action Types** | Defining `actions` props as `any` or loose strings instead of updating the strict `SduiAction` union. Breaks compile-time exhaustiveness gates. |
| **Hardcoded Color Codes** | Ad-hoc hexadecimal color values in components. Styling must use centralized design tokens. |
| **Non-Safe Parsers** | Parsing JSON layouts directly without try-catch or undefined checks, leading to app crashes on malformed layouts. |

---

## 🔄 AI Collaboration Cycle
1. **Define Schema**: Specify the layout in `sdui-schema.json`.
2. **Scaffold & Type**: Let the AI generate props shapes in `types.ts` and placeholders.
3. **Review Mappings**: Assert component alignments against design tokens.
4. **Run Mocks**: Switch to fallback schemas dynamically to verify layouts behavior.
